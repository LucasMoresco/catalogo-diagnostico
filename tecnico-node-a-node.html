8. O que o Vinícius fez diferente

Desligou 3 nós de propósito (todos presentes, disabled=true): Guard Telemetry, Get Automation Outcome, Merge Outcome → sem guarda de telemetria (confabula) e sem canal de verdade-de-ação. A lógica da guarda foi movida p/ um Normalize Output Moresco | BKP órfão (sem entrada/saída), e o Normalize Output ativo virou um wrapper de 234 chars (só JSON.parse).
Parser LIGADO — forte correlação com as respostas malformadas nos casos de ação. RAG = n8n_vectors_v3 (em ingestão). Prompt enxuto (14,5k). Tem Token Splitter p/ o RAG. (O log que adicionei tem o Log Push Status removido — bug meu de encadeamento.)

10. Pendências de porte (documentadas, ainda não no base)

Segundo consolidacao-support-agent-lucas.md, ainda não foram aplicados ao [Lucas] base: App Catalog + Attach Apps, WIPE no allowlist, e a recomendação de desligar o parser no base (o coerce() já cobre). Também há a nota de portar tudo p/ o v2 (FaB8KAYtKIksf0xp, cópia futura) e a auth do webhook a re-ligar no cutover.
Leitura de decisão (resumo técnico). O [Lucas] base concentra o hardening determinístico (Guard Telemetry, applyGuard, verdade-de-ação, logging, trava de idioma) com nada desativado. O que falta nele é exatamente o que o Demo já tem (App Catalog + WIPE + parser off). O Vinícius desligou as guardas e mantém o parser ligado — a combinação que explica confabulação + respostas malformadas. Caminho técnico: base [Lucas] + importar App Catalog/WIPE do Demo + desligar o parser.
