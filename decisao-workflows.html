Muita coisa aqui é toggle (guarda on/off, parser on/off, verdade-de-ação on/off, WIPE no allowlist). Ou seja: as diferenças são em grande parte de configuração, não de arquitetura — o que abre espaço pra combinar o melhor de cada um.

2. Por que isso importa (config → comportamento observado)

Vinícius confabula telemetria (diz "temperatura alta" com o device frio) → porque a Guarda está desligada. Sem a checagem hard, o modelo concorda com o usuário.
Vinícius quebra (resposta malformada) nos casos de ação (9.3, T.1/T.3/T.4) → forte correlação com o Output parser LIGADO (o parser engasga com a saída estruturada dos comandos).
Autonomous narra reinício falso ("I'm restarting now") → não tem seção de verdade-de-ação nem o canal de Automation Outcome.
Autonomous oferece UNINSTALL (DO-only) num device sem Device Owner → sem gate de modo de gestão.
Autonomous responde em inglês mesmo pro usuário PT → o prompt/idioma dele default é inglês (acerta só quando o usuário é EN).
[Lucas] é honesto (temperatura normal, não reinicia à toa, não narra sucesso falso) → Guarda ativa + verdade-de-ação ativa.
[Lucas] recusa demais / não resolve licença (9.3, T.3) → sem WIPE no allowlist e sem App Catalog; ele explica em vez de agir.
Autonomous é estável (nunca malformou) → parser desligado, mesmo motivo que protege o [Lucas].

3. Forças e fraquezas

#1

[Lucas] base (PKeMq)

  • ✓ Guarda de telemetria ativa → honesto, não age sem justificativa
  • ✓ Verdade-de-ação ativa (prompt + Automation Outcome) → não narra sucesso falso
  • ✓ Prompt mais completo (44,7k) e PT / segue idioma
  • ✓ Estável (não malformou)
  • ✗ Não resolve ação real (sem WIPE no allowlist, sem App Catalog) → recusa demais
  • ✗ Confirmação por texto ("responda SIM"), sem card
#2

Autonomous (original)

  • ✓ Estável (parser off), base de produção
  • ✓ Card de confirmação renderiza
  • ✓ Checa telemetria via tool (honesto no térmico)
  • ✗ Responde em inglês pro usuário PT
  • ✗ Sem verdade-de-ação → narra reinício que não executa
  • ✗ Sem gate de modo de gestão → oferece ação DO-only
  • ✗ Sem guarda hard → propõe RESTART em device saudável
#3

Vinícius (2mDb)

  • ✓ PT e card de confirmação
  • ✓ WIPE no allowlist (potencial de ação)
  • ✗ Parser ligado → respostas malformadas nos casos de ação (maior problema)
  • ✗ Guarda desligada → confabula telemetria
  • ✗ Verdade-de-ação desligada
  • ✗ RAG em ingestão (v3, incompleto) → comportamento ainda instável

4. Ranking e recomendação

1º — [Lucas] base é a melhor fundação. É o mais seguro e honesto (guarda + verdade-de-ação), o prompt mais maduro e o mais estável. O que falta nele é capacidade de ação (resolver e executar WIPE/limpeza com identifier). É mais fácil adicionar ação a uma base honesta do que adicionar honestidade a uma base solta.
2º — Autonomous é a base de produção estável, mas precisa de 3 correções pra ficar no nível: trava de idioma (PT), seção de verdade-de-ação e gate de modo de gestão.
3º — Vinícius, hoje, é o mais problemático. O parser ligado produz respostas malformadas nos casos de ação e a guarda desligada gera confabulação. Precisa de dois toggles (parser off, guarda on) antes de ser viável — e o RAG dele ainda está em ingestão.

5. Caminho recomendado (o "melhor dos três")

Como as diferenças são muito de configuração, o alvo ideal é uma combinação:

  • Partir da [Lucas] base (guarda ativa + verdade-de-ação + prompt maduro + parser controlado).
  • Enxertar a capacidade de ação: WIPE_APP_DATA/limpeza no allowlist + App Catalog pra resolver o identifier (foi o que fez o Demo ganhar no 9.3).
  • Trocar a confirmação por card (requires_confirmation) em vez do "responda SIM" em texto.
  • Ajustar o gate de modo de gestão pra gatear a oferta (não propor ação DO-only que vira no-op).

Isso mantém a honestidade do [Lucas] e ganha a capacidade de ação do Demo, sem herdar a confabulação/malformação do Vinícius.

Ressalva. O RAG ainda está em ingestão (o playbook do Vinícius está em n8n_vectors_v3, incompleto). O comportamento de "resolução de problemas" vai mudar conforme os playbooks sobem, então este comparativo é um snapshot.
